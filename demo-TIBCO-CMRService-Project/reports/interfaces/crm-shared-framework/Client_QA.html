How to use this pageThese are the points the analysis could not settle from the source alone. This page records them as of the date below; it does not collect answers and cannot send anything. Give your answers to your OSI consultant, or go through them together in the toolkit.

Can you provide the KPN EAI Common library (Common_2.2.2.projlib), including Base.xsd, ResultStatus.xsd, Errors.xsd, EAIMessages.xml and the source of the CommonXPathFunctions Java class?

The message header and status schemas, the transport to the back-end adapters, the exception-queue handler and the custom helper functions all live in this library, and it was not included in the export. The three shared message profiles and the error handler cannot be completed without it.

Awaiting an answer

If this is not answered: Header, status and error structures are reconstructed from how the CRMServices mappings use them; they are validated against real messages captured from the current system before go-live.

scope

How should the migrated integrations reach UCMAdapter for AddAccountReference, now that TIBCO Rendezvous will not be available to Boomi?

Today the call goes over TIBCO Rendezvous request/reply, which Boomi cannot connect to. The choice decides how the UCM AccountReference ADD operation and its message formats are built, and the same decision applies to every back-end call in the project.

Awaiting an answer

If this is not answered: EMS (JMS) request/reply to the same subject name, with an RV-to-EMS bridge or the adapter re-pointed to EMS by the client's middleware team.

connectivity

Which mail server should the migrated error notifications use, and who should receive them (To, CC, BCC) in each environment?

SMTP host, port, authentication, TLS and the From/To/CC/BCC lists are unknown: the mail settings file was not included in the export. Without them the mail connection and distribution list cannot be configured.

Awaiting an answer

If this is not answered: Notifications are built against a placeholder SMTP connection and an empty distribution table that must be filled in before testing.

environment

Should error e-mails keep including the full failing message, which contains contact personal data, or only the message ID, error code and description?

Error mails currently embed the full failing message (contact personal data). The answer decides the notification content in all four business interfaces.

Awaiting an answer

If this is not answered: Mails carry the service name, message ID, error code and error description only; the full message stays in the exception queue and in Boomi process reporting.

security

What is the name and expected message format of the enterprise exception queue that failed CRMServices messages are sent to, and which team or tool reads it?

The message format and destination of the exception queue, and whether failed messages are also rolled back or redelivered, are defined in the missing Common library. The Boomi error handler must produce records the existing exception tooling accepts.

Awaiting an answer

If this is not answered: Failures are sent to a queue named from the environment prefix plus a configurable name, in a simple XML record holding the error codes, message ID, original body and JMS properties. Downstream tooling may need adjusting.

data

Does any system or support process depend on the specific CRMServices and EAI error codes (for example CRMS-03021 'Backend replied with error' or EAI-03004 for a timeout)?

The error codes produced by the transport on timeout (EAI-03004) and the engine timeout code (BWENGINE-100067) are framework codes, and the retry rules of the contact-publication flow depend on them. Keeping the same codes keeps those rules and any monitoring working.

Awaiting an answer

If this is not answered: The existing CRMS codes are kept, and a Boomi timeout is reported as EAI-03004 so that retry rules behave as today. BWENGINE codes are not reproduced.

business-rule

Do any systems that read CRMServices messages rely on the exact format of the tracking timestamp or the 'Operations/CRMServices' application tag in the message header?

The exact output format of the TIBCO timestamp function must be matched so that consumers parsing the header timestamp are unaffected; the format cannot be determined from the export.

Awaiting an answer

If this is not answered: ISO 8601 date-time with milliseconds and time-zone offset is used, and the application tag is kept as 'Operations/CRMServices'.

data

Which EMS server addresses, and which dedicated service account, should the Boomi runtime use in each environment (development, test, production)?

The export holds only localhost defaults and a generic account name. Real values are needed to set up the shared EMS connection, and a least-privilege account is recommended.

Awaiting an answer

If this is not answered: The connection is built with environment extensions left empty, to be filled in by the client's EMS administrators at deployment.

environment

Should traffic between Boomi and EMS be encrypted (SSL/TLS)?

An SSL address is defined in the configuration, but the defaults use unencrypted connections and nothing shows which one production uses.

Awaiting an answer

If this is not answered: The same transport as today's production configuration is used once the EMS administrators confirm it; otherwise SSL is recommended.

security

Roughly how many failures, and how many new account or contact references, do the CRMServices integrations handle per day, and what is the busiest hour?

No volumes, rates or SLAs are stated anywhere in the export; they drive runtime sizing and the concurrency of the shared components.

Awaiting an answer

If this is not answered: Low volume (thousands per day or fewer), served by a single Boomi runtime with the same concurrency as today (10 sessions per listener).
